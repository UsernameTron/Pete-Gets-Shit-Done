<glob_semantics_examples>
Test inputs and expected behavior for `gitignoreGlobToRegex`:

| Input glob | Should MATCH (relative path) | Should NOT MATCH |
|------------|------------------------------|------------------|
| `*.md` | `a.md`, `index.md` | `sub/a.md`, `tests/foo.md` (single-segment only) |
| `**/*.md` | **`a.md` (root)**, `sub/a.md`, `a/b/c.md` | `a.txt`, `subdir` |
| `tests/**` | `tests`, `tests/a.md`, `tests/sub/b.md`, `tests/foo` | `test/a.md`, `nottests/x.md` |
| `tests/fixtures/doc-links/**` | `tests/fixtures/doc-links/clean/index.md`, `tests/fixtures/doc-links/edge/empty.md` | `tests/fixtures/doc-other/x.md`, `tests/x.md` |
| `.claude/skills/SKILL.md` | `.claude/skills/SKILL.md` | `.claude/skills/dream-memory-consolidation/SKILL.md`, `.claude/SKILL.md` |
| `docs/*.md` | `docs/x.md`, `docs/README.md` | `docs/sub/x.md` (single-segment) |
| `''` (empty string) | (gracefully match nothing) | any non-empty path |
| `*.{md,txt}` | (treat `{...}` as literal in v1; planner may opt to leave brace expansion unsupported) | n/a — out of scope |

The `**` semantics in gitignore are subtle: a leading `**/` matches zero or more directories (INCLUDING zero — root-level files match), and `/**` at end matches everything inside. The conversion rules:

1. **Special-case `**/` at the start of the glob.** The token `**/` represents "zero or more directories", so the converter MUST normalize a leading `**/` to a placeholder that, after the trailing transform, becomes a regex group matching `(?:.*\\/)?` (one or more dirs OR nothing). **Without this special case, `^.*/[^/]*\\.md$` will fail to match a root-level `a.md` because the trailing `/` after `.*` is mandatory.** This is the Codex HIGH concern from REVIEWS.md and is the core technical risk for Wave 2.
2. **Special-case `/**` at the end of the glob.** Trailing `/**` represents "this directory and everything below it", so a glob like `tests/**` should also match `tests` (the directory name itself if it appeared as a tracked file path).
3. Escape all regex meta-chars EXCEPT `*` and `?` (and the special tokens `**/` and `/**` are stripped before this step).
4. Replace each remaining `**` with `.*` (matches any chars including `/`).
5. Replace each remaining single `*` with `[^/]*` (matches any chars EXCEPT `/`).
6. Anchor with `^` and `$`.

Order matters: substitute the `**/` and `/**` special-case tokens FIRST (with placeholders), then escape, then `**` -> `.*`, then `*` -> `[^/]*`, then resolve placeholders.

Worked examples (manual trace):

- `'**/*.md'` -> leading `**/` lifted -> `LDS*.md` -> escape `.` -> `LDS*\\.md` -> `*` -> `LDS[^/]*\\.md` -> resolve `LDS` -> `(?:.*\\/)?[^/]*\\.md` -> final `^(?:.*\\/)?[^/]*\\.md$`. Matches `a.md` (the optional group is empty), `sub/a.md` (group is `sub/`), and `a/b/c.md` (group is `a/b/`). Does NOT match `a.txt`.
- `'tests/**'` -> trailing `/**` lifted -> `tests TSD` -> escape (nothing to escape in `tests`) -> resolve `TSD` -> `tests(?:\\/.*)?` -> final `^tests(?:\\/.*)?$`. Matches `tests`, `tests/a.md`, `tests/sub/b.md`. Does NOT match `test/a.md`.
- `'*.md'` (no `**`) -> escape `.` -> `*\\.md` -> `*` -> `[^/]*\\.md` -> final `^[^/]*\\.md$`. Matches `a.md`, `index.md`. Does NOT match `sub/a.md`.
- `''` -> returns `/(?!)/` — never matches any path. Graceful no-op.

This algorithm closes the Codex HIGH finding (`**/*.md` correctly matches both root files and nested files) and the Gemini LOW finding (empty-string glob handled gracefully).

**Unsupported gitignore features (documented in v1):** leading `!` negation, brace-expansion `{a,b}`, single-char `?` (treated as literal), and POSIX character classes. These limitations MUST appear in the validator's `--help` output (or header comment) so call-site authors are not surprised.
</glob_semantics_examples>

**2. Add `gitignoreGlobToRegex` function** between the existing constants (`LINK_RE`, `EXTERNAL_RE`) and the `toGfmSlug` function. The leading `**/` and trailing `/**` special-cases are required to satisfy the REVIEW HIGH glob-semantics finding (Codex) — without them, `**/*.md` does NOT match a root-level `a.md` because the `.*/` would require a slash in the path, breaking the gitignore-compatible `**/` semantics that match zero-or-more directories.

```javascript
// gitignoreGlobToRegex section divider here

/**
 * Convert a gitignore-style glob to a RegExp anchored at start and end.
 *
 * Supported semantics (subset sufficient for v2.8 CI call-site exempt list):
 *   - Leading `**\/` matches zero or more directories (incl. zero -- root files match)
 *   - Trailing `/**` matches '' or '/anything' (the directory itself plus everything below)
 *   - Bare `**` matches any chars including `/`
 *   - `*` matches a single segment (zero or more chars EXCEPT `/`)
 *   - All other regex meta-chars are escaped: . ( ) [ ] { } + $ ^ | \ ?
 *   - Pattern is anchored: the full repo-relative path must match
 *   - Empty-string glob returns a never-match regex (graceful no-op)
 *
 * NOT SUPPORTED in v1 (planner choice; can be added if call-site needs surface):
 *   - Leading `!` negation (CONTEXT D-07)
 *   - Brace expansion `{a,b}`
 *   - `?` single-char wildcard (treated as literal)
 *   - POSIX character classes
 *
 * Order matters: lift the special-case `**/`-leading and `/**`-trailing tokens
 * to placeholders BEFORE escaping, so the regex meta-char escape step does not
 * see them; then escape; then resolve `*` and remaining `**`; then resolve
 * placeholders to their final regex meanings.
 *
 * Exported as a public API surface for direct unit testing (see REVIEW MEDIUM
 * disposition in this plan's review_disposition section).
 *
 * @param {string} glob  Gitignore-style glob pattern
 * @returns {RegExp}     Regex matching repo-relative paths, anchored ^...$
 */
function gitignoreGlobToRegex(glob) {
  // Empty-string glob is a graceful no-op: never matches any path.
  // Friendlier than throwing for call sites that may accumulate args programmatically.
  if (glob === '') {
    return /(?!)/;
  }

  // Step 1: lift the special-case leading-`**/` and trailing-`/**` tokens
  // to placeholders so subsequent steps don't mis-handle them.
  const LEADING_DOUBLE_SLASH = 'LDSPLACEHOLDER';
  const TRAILING_SLASH_DOUBLE = 'TSDPLACEHOLDER';
  const STANDALONE_DOUBLE = 'DBLPLACEHOLDER';

  let pat = glob;
  if (pat.startsWith('**/')) {
    pat = LEADING_DOUBLE_SLASH + pat.slice(3);
  }
  if (pat.endsWith('/**')) {
    pat = pat.slice(0, -3) + TRAILING_SLASH_DOUBLE;
  }
  // Lift any remaining bare `**` (e.g., embedded mid-pattern).
  pat = pat.replace(/\*\*/g, STANDALONE_DOUBLE);

  // Step 2: escape regex metacharacters EXCEPT '*' (and our placeholders).
  // We escape '?' too — gitignore treats '?' as single-char wildcard, but the
  // v1 use case is literal paths and `**` directory globs, so treating '?'
  // as literal is safer than half-implementing it.
  pat = pat.replace(/[.+^$|()\[\]{}\\?]/g, '\\$&');

  // Step 3: substitute remaining single '*' with [^/]* (single-segment match).
  pat = pat.replace(/\*/g, '[^/]*');

  // Step 4: resolve placeholders to their regex meanings.
  pat = pat
    .replace(new RegExp(LEADING_DOUBLE_SLASH, 'g'), '(?:.*\\/)?')   // zero or more dirs at start (trailing '/' is optional)
    .replace(new RegExp(TRAILING_SLASH_DOUBLE, 'g'), '(?:\\/.*)?')  // '' or '/anything' at end
    .replace(new RegExp(STANDALONE_DOUBLE, 'g'), '.*');             // bare ** matches anything incl '/'

  return new RegExp('^' + pat + '$');
}
```

**3. Update `discoverTrackedFiles` signature** to accept an optional `excludeRegexes` parameter. Locate the existing function (around line 336) and modify its body to apply the filter after both the `git ls-files` path and the `globMdFiles` fallback path. The full updated function:

```javascript
/**
 * Discover all tracked Markdown files via git ls-files.
 * Falls back to a recursive glob if git is unavailable (non-git directory or
 * fixture directory used in unit tests).
 *
 * If excludeRegexes is provided, files whose REPO-RELATIVE path matches any
 * regex are filtered out. Conversion abs-path -> repo-relative uses
 * `path.relative(repoRoot, abs)` and normalizes path separators to `/` on
 * Windows so glob authors don't have to think about backslashes.
 *
 * @param {string} repoRoot         Absolute path to repo root (or fixture root)
 * @param {RegExp[]} [excludeRegexes]  Optional exclude regexes
 * @returns {string[]}              Absolute paths to surviving .md files
 */
function discoverTrackedFiles(repoRoot, excludeRegexes) {
  let files;
  try {
    const out = execFileSync('git', ['ls-files', '--', '*.md'], {
      cwd: repoRoot,
      encoding: 'utf8',
      stdio: ['ignore', 'pipe', 'ignore'],
    });
    const tracked = out
      .split('\n')
      .filter(Boolean)
      .map(f => path.resolve(repoRoot, f));
    if (tracked.length > 0) {
      files = tracked;
    }
  } catch {
    // git unavailable or repoRoot is not a git working tree — fall through.
  }
  if (!files) files = globMdFiles(repoRoot);

  if (!excludeRegexes || excludeRegexes.length === 0) return files;

  return files.filter(abs => {
    const rel = path.relative(repoRoot, abs).split(path.sep).join('/');
    return !excludeRegexes.some(rx => rx.test(rel));
  });
}
```
