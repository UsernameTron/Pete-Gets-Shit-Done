## Goal

Make the GSD engine smarter — route models by task complexity, learn from execution history, adapt workflow behavior automatically.

## Constraints

- Zero-dependency CommonJS
- File-based storage only (JSONL)
- All new parameters optional
- All new config keys have safe defaults
- No breaking changes to existing commands

## Key Accomplishments

1. **Dynamic Model Routing** — `dynamicSelect()` in model-profiles.cjs maps task complexity to model tiers (budget/balanced/quality). Gated behind `routing_strategy` config key with `static` default for zero-regression.

2. **Task Classification Engine** — New `classify.cjs` module with weighted scoring algorithm. Produces complexity levels (trivial/standard/complex/critical) from phase metadata, plan inventory, and requirement counts. Adaptive workflow gates adjust research depth, verification rigor, and parallelization wave size.

3. **Execution History & Pattern Learning** — New `history.cjs` module with JSONL-based append-only storage. Records execution outcomes, supports filtered queries, detects patterns (failure rates, model performance, cost distribution). Auto-rotates at 1000 records. CLI commands: list, stats, prune.

4. **History-Aware Routing** — When `routing_strategy: 'auto'`, dynamicSelect() uses execution history patterns to influence model selection, learning from past agent performance.

5. **Config Migration v1→v2** — Migration registry extended with version 2. Adds `routing_strategy: 'static'` and `adaptive: false` defaults. Existing configs auto-migrate without user action.

6. **Full Integration & Documentation** — E2E pipeline test (classify→route→record→learn), performance benchmarks (<5ms overhead), coverage gates (98%+ on new modules), all living documents updated.

## Key Decisions

| Decision | Rationale |
|----------|-----------|
| Optional taskContext for backward compat | New dynamic routing parameter must be optional — absent = exact v1.9 behavior |
| JSONL for execution history | Append-only, zero-dep, line-by-line parseable, trivially rotatable — no SQLite |
| Rule-based pattern detection | Zero-dependency constraint forbids ML libs — heuristic/rule-based only |
| routing_strategy defaults to static | Existing users see zero behavior change until explicit opt-in |
| Profile bounding in dynamicSelect | Quality profile never downgrades, budget caps at balanced — respects user cost/quality intent |
| Lazy require in dynamic branch | Avoids circular deps, loaded only when routing_strategy !== 'static' |
