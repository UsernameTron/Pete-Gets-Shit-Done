### Inconsistency: Phase 36 Tier Labels for gsd-debugger and gsd-planner

**Severity:** INFO (non-blocking)

Phase 36's AUDIT-03 report states "Declared Tier: Modify" for gsd-debugger and gsd-planner in its Check 2 table. The actual agent source files contain `# Tier: Full`. Phase 35's report correctly identifies them as "Declared Tier: Full". Phase 36's explanatory note (line 99) compounds the error by stating "the declared tiers in the source files are `# Tier: Modify`".

The final verdict (15/15 PASS) is correct in both reports -- the error is in the intermediate documentation, not in the conclusion.

**Recommendation:** Correct the Phase 36 AUDIT-REPORT.md Check 2 table and explanatory note to show "Declared Tier: Full" for gsd-debugger and gsd-planner, matching Phase 35 and the actual source files.

### Observation: Hook Count Discrepancy

**Severity:** INFO (non-blocking)

Phase 36 audited 16 hooks (15 user-level + 1 project-level). README.md line 69 reports "Runtime hooks: 15 (5 execution + 10 governance)". The project-level hook (lesson-capture-gate.cjs) is not counted in the README total. This is arguably correct since the README describes what GSD ships, and the project-level hook is specific to this repository. However, the discrepancy could confuse readers comparing the audit report to the README.

### Observation: Installed vs Source Discrepancies

Phase 35 identified that the installed `ship.md` at `~/.claude/get-shit-done/` does not contain the gsd-validator-hub routing that exists in the source `workflows/ship.md`. Phase 36 identified 12 source commands not in the installer. Both are deployment gaps (the source code is correct but the installed runtime is out of date). These are noted for awareness but are not integration failures -- they are deployment artifacts that resolve on next npm publish.
