## Phase Details

### Phase 2: Coverage Audit
**Goal**: Current test coverage is measured, gaps are identified with priority ranking, and a baseline is documented before any new tests are written
**Depends on**: Phase 1 (v1.0 -- complete)
**Requirements**: COV-01, COV-02, COV-03
**Success Criteria** (what must be TRUE):
  1. Running the coverage tool produces a per-module line/branch coverage report for every module in the project
  2. A gap analysis document exists listing untested code paths ranked by priority (security-critical > operational > utility)
  3. The pre-expansion coverage baseline is captured in a committed file that future phases can compare against
**Plans:** 2 plans
Plans:
- [x] 02-01-PLAN.md -- Expand c8 coverage instrumentation to all JS/CJS source files
- [x] 02-02-PLAN.md -- Generate gap analysis and coverage baseline documents

### Phase 3: Unit Test Expansion
**Goal**: All identified coverage gaps in governance scripts, plugin integration, hook behavior, and command handlers are closed with targeted unit tests
**Depends on**: Phase 2
**Requirements**: UNIT-01, UNIT-02, UNIT-03, UNIT-04
**Success Criteria** (what must be TRUE):
  1. Governance scripts (scaffold, health-check, install-plugins) each have dedicated test files with passing tests covering their main paths
  2. Plugin loading, command routing, and skill resolution paths are tested -- loading a plugin, routing a command, and resolving a skill each have at least one test
  3. Hook lifecycle events, matcher patterns, and exit code handling each have test coverage
  4. Every command handler identified as uncovered in Phase 2 has at least one test exercising its primary behavior
**Plans**: 4 plans (complete)
Plans:
- [x] 03-01-PLAN.md -- Governance scripts unit tests
- [x] 03-02-PLAN.md -- Plugin and command routing tests
- [x] 03-03-PLAN.md -- Hook lifecycle and matcher tests
- [x] 03-04-PLAN.md -- Command handler coverage

### Phase 4: Integration Test Suite
**Goal**: End-to-end workflows and cross-component interactions are validated through integration tests that exercise real code paths (not mocks)
**Depends on**: Phase 3
**Requirements**: INTG-01, INTG-02, INTG-03
**Success Criteria** (what must be TRUE):
  1. An integration test exercises the full GSD flow from fresh install through /prime, /gsd:plan-phase, /gsd:execute-phase, and /gsd:verify-work -- and passes
  2. Governance hook enforcement scenarios (docs check, secrets scan, branch protection) are tested and produce expected block/allow behavior
  3. Plugin loading and command routing works correctly across plugin types in an integration context (not just unit-level mocks)
**Plans:** 3/3 plans complete
Plans:
- [x] 04-01-PLAN.md -- Full GSD CLI flow: command chain + state progression integration tests
- [x] 04-02-PLAN.md -- Governance hook enforcement: advisory output + template wiring integration tests
- [x] 04-03-PLAN.md -- Plugin ecosystem coherence: cross-plugin uniqueness + reference integrity tests

### Phase 5: CI Pipeline Hardening
**Goal**: CI pipeline is reliable across platforms with coverage reporting and no timeout failures
**Depends on**: Phase 4
**Requirements**: CI-01, CI-02, CI-03
**Success Criteria** (what must be TRUE):
  1. base64-scan.sh completes without timeout on large diffs by excluding binary files
  2. CI pipeline outputs a coverage report on every run showing per-module line/branch percentages
  3. All CI checks pass on Linux, macOS, and Windows without platform-specific failures
**Plans:** 2/2 plans complete
Plans:
- [x] 05-01-PLAN.md -- Harden base64-scan.sh with size cap and total timeout
- [x] 05-02-PLAN.md -- CI coverage reporting and cross-platform matrix overhaul
