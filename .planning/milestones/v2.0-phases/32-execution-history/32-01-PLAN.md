# PLAN — Phase 32.1: history.cjs Module — Core Functions

## Objective

Create the `history.cjs` module with three exported functions: `recordExecution()`, `queryHistory()`, and `detectPatterns()`. This module handles JSONL-based execution history — append, query, and pattern analysis. It lives at Layer 2 because it needs `core.cjs` for `debugLog()`.

## Architecture Constraints

- **Layer 2**: May import `core.cjs` (Layer 1) for `debugLog`. No Layer 3 imports.
- **Zero external dependencies**: CommonJS, no npm packages.
- **File I/O via Node.js builtins**: `fs`, `path` only.
- **JSONL format**: One JSON object per line, append-only for writes.
- **deepFreeze convention**: All exported constant objects must be frozen.
- **Defensive**: All functions handle missing files, empty files, malformed lines gracefully.

### Helper: getHistoryPath(cwd)

### Helper: parseJsonlSafe(filePath)
Reads a JSONL file, returns array of parsed objects. Skips blank lines and malformed JSON lines (logs warning via debugLog). Returns empty array if file doesn't exist.

```js
function parseJsonlSafe(filePath) {
  if (!fs.existsSync(filePath)) return [];
  const lines = fs.readFileSync(filePath, 'utf8').split('\n');
  const records = [];
  for (const line of lines) {
    const trimmed = line.trim();
    if (!trimmed) continue;
    try {
      records.push(JSON.parse(trimmed));
    } catch {
      // Skip malformed lines — defensive against corruption
    }
  }
  return records;
}
```

## Task 2: recordExecution(cwd, phaseNum, planNum, outcome) — INTEL-13

### Parameters
- `cwd` — project root
- `phaseNum` — phase number (number or string, coerced to number)
- `planNum` — plan number (number or string, coerced to number)
- `outcome` — object with optional fields:

```js
{
  agent: 'gsd-executor',     // string, default: 'unknown'
  model_used: 'sonnet',      // string, default: null
  duration_ms: 12500,        // number, default: null
  outcome: 'pass',           // one of OUTCOME_VALUES, required
  error_code: null,          // string, default: null
  files_changed: 3,          // number, default: 0
}
```

### Behavior

1. Validate `outcome.outcome` is one of OUTCOME_VALUES — throw if invalid
2. Build record object:
```js
{
  timestamp: new Date().toISOString(),
  phase: Number(phaseNum),
  plan: Number(planNum),
  agent: outcome.agent || 'unknown',
  model_used: outcome.model_used || null,
  duration_ms: outcome.duration_ms ?? null,
  outcome: outcome.outcome,
  error_code: outcome.error_code || null,
  files_changed: outcome.files_changed || 0,
}
```
3. Ensure directory exists: `fs.mkdirSync(path.join(cwd, HISTORY_DIR), { recursive: true })`
4. Append to file: `fs.appendFileSync(historyPath, JSON.stringify(record) + '\n')`
5. Return the record object

## Task 3: queryHistory(cwd, filters) — INTEL-14

### Parameters
- `cwd` — project root
- `filters` — object with optional fields:

```js
{
  agent: 'gsd-executor',        // string — exact match
  phaseRange: [30, 32],         // [min, max] inclusive
  outcome: 'fail',              // string — exact match
  dateRange: ['2026-01-01', '2026-12-31'], // [start, end] ISO date strings
  limit: 50,                    // max records to return (default: all)
}
```

### Behavior

1. Read all records via `parseJsonlSafe()`
2. Apply filters in order (each narrows the set):
   - `agent`: `record.agent === filters.agent`
   - `phaseRange`: `record.phase >= min && record.phase <= max`
   - `outcome`: `record.outcome === filters.outcome`
   - `dateRange`: `record.timestamp >= start && record.timestamp <= end` (string comparison works for ISO dates)
3. If `limit` specified, take last N records (most recent)
4. Return `{ records, total: filteredCount }`

If no filters provided, returns all records.

## Task 4: detectPatterns(cwd) — INTEL-15

### Behavior

1. Read all records via `parseJsonlSafe()`
2. If fewer than 5 records, return `{ patterns: [], insufficient_data: true }`
3. Compute aggregations:

**Frequently-failing phases:**
- Group by phase, calculate failure rate per phase
- Flag phases with failure rate > 30% AND at least 3 executions

**Agents needing quality tier:**
- Group by agent, check if any agent has >50% failures when using budget/balanced tier models
- Compare failure rates across model tiers per agent

**Average execution times by complexity:**
- This requires `complexity` in the record — but records don't have it yet (Phase 33 wires this)
- For now, group by phase and calculate average `duration_ms` (skip null durations)

**Cost distribution (simplified):**
- Count records by `model_used` to show model usage distribution

4. Return:
```js
{
  patterns: [
    { type: 'failing_phase', phase: 31, failure_rate: 0.45, executions: 11 },
    { type: 'agent_tier_mismatch', agent: 'gsd-executor', recommended_tier: 'quality', evidence: '60% fail on budget' },
    // ...
  ],
  summary: {
    total_executions: 150,
    overall_pass_rate: 0.82,
    avg_duration_ms: 8500,
    model_distribution: { sonnet: 80, haiku: 50, opus: 20 },
  },
  insufficient_data: false,
}
```
