# PLAN — Phase 31.3: Init Command Wiring — classifyTask Integration

## Objective

Wire `classifyTask()` from classify.cjs into both init commands (`cmdInitExecutePhase` and `cmdInitPlanPhase`). When `config.adaptive` is true, include `task_classification` in the init output JSON so workflow prompts can reference the classification result.

## Architecture Decision

- `classify.cjs` is Layer 0, `init.cjs` is Layer 3 — import direction is valid
- Use lazy require inside the adaptive branch to avoid loading classify.cjs when `adaptive: false`
- This mirrors the Phase 30 pattern where `model-profiles.cjs` is lazy-required inside the dynamic routing branch of `resolveModelInternal()`

## Task 1: Add classifyTask to cmdInitExecutePhase (INTEL-10, INTEL-12)

In `get-shit-done/bin/lib/init.cjs`, in `cmdInitExecutePhase()` (starts at line 77):

After the existing `taskContext` computation (line 111) and before the result object (line 113), add:

```js
// Task classification for adaptive workflows (INTEL-10, INTEL-12)
let task_classification = null;
if (config.adaptive) {
  const { classifyTask } = require('./classify.cjs');
  const classContext = {
    reqIds: phase_req_ids,
    failureRate: null, // Phase 32 will supply historical failure rate
  };
  task_classification = classifyTask(phaseInfo, phaseInfo?.plans, classContext);
}
```

Then add `task_classification` to the result object (after `phase_req_ids`):

```js
task_classification,
```
