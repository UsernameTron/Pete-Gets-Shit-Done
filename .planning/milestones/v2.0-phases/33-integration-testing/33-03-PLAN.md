## Task 1: Update model-profiles.md Reference

### File: `get-shit-done/references/model-profiles.md`

### Changes

1. **Add Dynamic Routing section** after the existing profile definitions table:

   ```markdown
   ## Dynamic Model Routing

   When `routing_strategy` is set to `dynamic` or `auto`, the engine uses task signals
   to select models instead of static profile mappings.

   ### How It Works

   1. **Classification**: `classifyTask()` analyzes phase metadata, plan inventory, and
      requirement count to produce a complexity level (trivial, standard, complex, critical)
   2. **Routing**: `dynamicSelect()` maps complexity to a model tier:
      - `trivial` -> budget tier (haiku-class)
      - `standard` -> balanced tier (sonnet-class)
      - `complex` -> quality tier (opus-class)
      - `critical` -> quality tier with override logging
   3. **History influence** (auto mode only): When execution history exists, past failure
      rates and model performance inform tier selection

   ### Routing Strategies

   | Strategy | Behavior |
   |----------|----------|
   | `static` (default) | Uses `model_profile` mapping. v1.9 behavior. |
   | `dynamic` | Classification-based routing. Ignores `model_profile` for agent selection. |
   | `auto` | Dynamic routing enhanced by execution history patterns. |
   ```

2. **Add Classification Signals subsection**:

   Document the signals extracted by `extractSignals()`:
   - `file_count` -- number of files in plan
   - `requirement_count` -- number of requirements in phase
   - `phase_type` -- inferred from phase name keywords (research, execute, verify, etc.)
   - `has_dependencies` -- whether plan depends on other plans
   - `plan_count` -- number of plans in phase

3. **Add Complexity Levels table**:

   | Level | Signals | Typical Phase Types |
   |-------|---------|---------------------|
   | trivial | low file count, few requirements, simple phase type | config, cleanup |
   | standard | moderate signals, no strong complexity indicators | execute, plan |
   | complex | high file count OR many requirements OR research phase | research, refactor |
   | critical | multiple strong signals OR explicit override | security, migration |

   ```markdown
   ### routing_strategy
   - **Type**: string
   - **Values**: `static`, `dynamic`, `auto`
   - **Default**: `static`
   - **Added in**: v2.0 (config_version 2)

   Controls how the engine selects models for agent tasks.
   - `static`: Uses the `model_profile` mapping (v1.9 behavior, zero overhead)
   - `dynamic`: Classifies task complexity and routes to appropriate model tier
   - `auto`: Dynamic routing enhanced by execution history analysis

   Migration: Existing configs are automatically migrated to config_version 2.
   The `routing_strategy` key is added with value `static` if not present.
   ```

2. **Add `adaptive` key**:

   ```markdown
   ### adaptive
   - **Type**: boolean
   - **Default**: `false`
   - **Added in**: v2.0 (config_version 2)

   Feature flag for adaptive workflow behavior. When `true`:
   - Task classification runs during init commands
   - Workflow gates may be adjusted based on complexity
   - Classification result included in init output

   Requires: `routing_strategy` set to `dynamic` or `auto` for full effect.
   ```

3. **Add Config Version section** explaining the migration system:

   ```markdown
   ## Config Versioning

   GSD uses a versioned migration system for config.json. The current version is **2**.

   | Version | Changes |
   |---------|---------|
   | 0 -> 1 | Migrated `depth` to `granularity`, `multiRepo` to `sub_repos` |
   | 1 -> 2 | Added `routing_strategy: 'static'` and `adaptive: false` defaults |

   ```

## Task 3: Update USER-GUIDE.md

### File: `docs/USER-GUIDE.md`

### Changes

1. **Add "Intelligence Layer" section** (new section, place after existing workflow sections):

   ```markdown
   ## Intelligence Layer (v2.0)

   GSD v2.0 adds optional intelligence features that make the engine smarter about
   model selection, task classification, and workflow adaptation.

   ### Quick Start

   All intelligence features are **off by default**. To enable:

   1. Edit `.planning/config.json`
   2. Set `routing_strategy` to `dynamic` (or `auto` for history-aware routing)
   3. Set `adaptive` to `true` for task classification

   ### Dynamic Model Routing

   Instead of using the same model tier for every task, dynamic routing selects
   models based on task complexity:

   - Simple config changes get fast, cheap models (budget tier)
   - Standard development gets balanced models
   - Complex architectural work gets the most capable models (quality tier)

   ### Execution History

   GSD tracks execution outcomes in `.planning/history/executions.jsonl`. Use CLI:

   - `gsd-tools history list` -- show recent executions
   - `gsd-tools history stats` -- show patterns and pass rates
   - `gsd-tools history prune` -- clean old records

   When `routing_strategy: 'auto'`, history patterns influence model selection.
   ```
