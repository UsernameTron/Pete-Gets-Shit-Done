# Plan 19-01: Feature Flags for Experimental Capabilities

## Objective

Add a lightweight feature flag system to core.cjs that gates experimental features behind named toggles, configurable via GSD config.

## Tasks

### Task 1: Add createFeatureFlags factory to core.cjs

**File:** `get-shit-done/bin/lib/core.cjs`

Add after the createCancelToken section (~line 142):

```javascript
function createFeatureFlags(config) {
  const flags = (config && config.features) || {};
  return {
    isEnabled(name) {
      return flags[name] === true;
    },
    listFlags() {
      return Object.keys(flags);
    },
    toJSON() {
      return { ...flags };
    }
  };
}
```

Export `createFeatureFlags` from module.exports.

### Task 2: Add `features` key to config.cjs hardcoded defaults

**File:** `get-shit-done/bin/lib/config.cjs`

In `buildNewProjectConfig` hardcoded defaults object, add:
```javascript
features: {},
```

Ensure the three-level merge handles `features` like other top-level keys:
```javascript
features: { ...(hardcoded.features || {}), ...(userDefaults.features || {}), ...(choices.features || {}) },
```

### Task 3: Write tests

**File:** `tests/core.test.cjs`

Add test block for `createFeatureFlags`:
1. Returns object with isEnabled, listFlags, toJSON methods
2. `isEnabled('x')` returns false when flag not set
3. `isEnabled('x')` returns true when `features: { x: true }`
4. `isEnabled('x')` returns false when `features: { x: false }`
5. `listFlags()` returns array of flag names
6. `toJSON()` returns copy of flags object
7. Handles null/undefined config gracefully
8. Handles config without features key gracefully

**File:** `tests/config.test.cjs` (if exists, else add to core tests)

1. Verify `features` key present in buildNewProjectConfig output
2. Verify features merge from defaults
