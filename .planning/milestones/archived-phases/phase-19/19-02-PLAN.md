# Plan 19-02: Wire validateShellArg to Production Caller

## Objective

Create at least one production code path that uses `validateShellArg()` from security.cjs, eliminating the zero-caller tech debt.

## Architecture Constraint

core.cjs CANNOT import security.cjs (Layer 0 → Layer 1 upward import violation). Wiring must happen in Layer 3 modules (commands.cjs, verify.cjs) that already import both modules.

## Tasks

### Task 1: Add validated git execution wrapper in commands.cjs

**File:** `get-shit-done/bin/lib/commands.cjs`

At the top of the module (after existing requires), ensure security.cjs is imported:
```javascript
const { validateShellArg } = require('./security.cjs');
```

Add a thin wrapper function:
```javascript
function execGitValidated(cwd, args) {
  const validatedArgs = args.map((arg, i) => {
    // Skip git subcommands and flags (start with -)
    if (i === 0 || arg.startsWith('-')) return arg;
    return validateShellArg(arg, `git arg[${i}]`);
  });
  return execGit(cwd, validatedArgs);
}
```

### Task 2: Wire execGitValidated at 2-3 user-input call sites

**File:** `get-shit-done/bin/lib/commands.cjs`

Identify call sites where user-derived strings flow into git commands. Replace `execGit` with `execGitValidated` at these sites:

1. **Branch creation** — where branch names come from user input or plan names
2. **Commit message** — where commit messages contain user-provided text
3. **File path arguments** — where file paths are user-derived

Only replace call sites where the args contain user-derived values. Leave internal git calls (like `git status`, `git log`) using plain `execGit`.

### Task 3: Write tests

**File:** `tests/commands.test.cjs` (or appropriate test file)

1. `execGitValidated` passes clean args through to execGit
2. `execGitValidated` throws on arg with shell operators (`;`, `|`, `&`)
3. `execGitValidated` throws on arg with null bytes
4. `execGitValidated` skips validation for flags (args starting with `-`)
5. `execGitValidated` skips validation for git subcommand (first arg)

## Acceptance Criteria

- [ ] `validateShellArg` has at least 1 production caller (was 0)

- [ ] 2-3 user-input git call sites use validated wrapper
- [ ] 5+ tests passing for validation behavior
- [ ] No regressions — internal git calls unchanged
