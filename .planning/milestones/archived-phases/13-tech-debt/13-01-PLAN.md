### Task 4: Wire gsd-validator-hub into /gsd:ship Workflow (DEBT-04)

**File to modify:** `commands/gsd/ship.md`

Add a pre-PR validation step that spawns gsd-validator-hub with `target: ecosystem`.
This runs as a read-only quality gate before creating the PR.

**Insertion point:** After the existing workflow steps that prepare the PR body, but before
the `gh pr create` step. Add a new section:

```markdown
## Pre-PR Validation

Before creating the PR, run an agent ecosystem health check:

1. Spawn gsd-validator-hub as a subagent with:
   - `target: ecosystem`
   - Input: project root path
   - Contract: read-only validation, return structured report
2. If result is FAIL: log the critical issues in the PR body as a "Known Issues" section
   but do NOT block the PR. Ecosystem validation failures are informational at ship time.
3. If result is PASS or WARN: note in PR body that ecosystem validation passed.
```

**Why ship and not finalize:** The ship command creates PRs — the natural handoff point
where quality gates matter most. Finalize already has 8 gates and is meant for milestone
closure, not per-feature validation. Validate-phase is about Nyquist audits, which is
a different concern.

**Verification:**
1. Read the modified `commands/gsd/ship.md` and confirm the new section exists.
2. Confirm gsd-validator-hub agent file has the correct tools (Read, Bash, Glob, Grep)
   and `disallowedTools: Write, Edit` — ensuring it cannot modify anything during the
   ship workflow.
