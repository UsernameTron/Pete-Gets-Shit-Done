# Plan 08-01: Shell & Output Hardening

## Goal
Harden shell argument validation to block metacharacters that could enable command injection, and add a truncation sentinel to `output()` as a safety net if temp file creation fails.

## Tasks

### Task 1: Block shell metacharacters (SEC-03)
**File:** `get-shit-done/bin/lib/security.cjs`
**Function:** `validateShellArg()` (lines 262-278)
**Current:** Only rejects null bytes and `$()` / backtick command substitution
**Fix:** Add rejection for:
- Shell operators: `;`, `|`, `&`
- Redirects: `>`, `<`
- Newlines: `\n`, `\r`
- Tilde expansion: `~` followed by a username (e.g., `~root`)

**Preserve:** Dollar signs not in substitution context (e.g., `$50`) — existing test covers this.

### Task 2: Truncation sentinel in output() (SEC-04)
**File:** `get-shit-done/bin/lib/core.cjs`
**Function:** `output()` (lines 159-181)
**Current:** Large payloads write to temp file; no fallback if temp file write fails
**Fix:** Wrap temp file creation in try/catch. On failure, truncate JSON to 50KB and append `\n__GSD_TRUNCATED__` sentinel marker so consumers know data was lost.

### Task 3: Tests
- Add tests for each blocked metacharacter in `validateShellArg()`
- Add test for truncation sentinel when temp file write fails
- Verify existing tests still pass

## Acceptance Criteria
- [ ] `validateShellArg()` rejects `;`, `|`, `&`, `>`, `<`, `\n`, `\r`, `~user`
- [ ] `validateShellArg()` still allows `$50`, `hello world`, `hello-world`
- [ ] `output()` produces `__GSD_TRUNCATED__` sentinel on temp file failure
- [ ] All existing tests pass
- [ ] New tests cover both fixes
