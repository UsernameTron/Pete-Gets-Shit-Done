**Discovery helper** (reuse pattern from plugin-loading.test.cjs):

Write a `discoverPlugins()` function that scans `plugins/` for directories containing `plugin.json` or `.claude-plugin/plugin.json`. Returns array of `{ name, dir, manifest }`. Also discover GSD commands from `get-shit-done/commands/`.

**Describe block 1: "cross-plugin command name uniqueness"** (per D-08)

1. **No command name collisions across all plugins** -- Collect all command filenames from `plugins/*/commands/` directories AND `get-shit-done/commands/`. Strip extensions to get command names. Assert no duplicates. If duplicates found, the assertion message should list which plugins have the collision.

2. **No skill name collisions across all plugins** -- Collect all skill directory names from `plugins/*/skills/`. Assert no duplicates across different plugins. (Same skill name in different plugins would cause routing ambiguity.)

3. **No agent name collisions across all plugins** -- Collect all agent filenames (without .md extension) from `plugins/*/agents/`. Assert no duplicates across different plugins.

**Describe block 2: "cross-reference integrity"** (per D-08)

1. **All command files referenced in manifests exist on disk** -- For each plugin, if `manifest.commands` array exists, verify each referenced command file exists. If manifests don't list commands explicitly, scan the commands/ directory and verify each file is non-empty and readable.

2. **All skill directories have valid SKILL.md** -- For every skill subdirectory across all plugins, assert SKILL.md exists and is non-empty.

3. **All agent .md files have name and description frontmatter** -- For every .md file in agents/ across all plugins, read content, verify it starts with `---`, has closing `---`, and contains `name:` and `description:` fields in frontmatter.

4. **GSD commands directory exists and has workflow files** -- Assert `get-shit-done/commands/` exists and contains at least 5 .md files (the core GSD workflows). This validates the GSD plugin's command surface is intact.

5. **Cross-plugin skill references resolve** -- Read each SKILL.md across all plugins. If any SKILL.md content references another skill by name (pattern: `@skill:skillname` or mentioning a skill from another plugin), verify that skill exists. If no cross-references found, the test passes trivially (no broken refs = coherent).

**Describe block 3: "no dangling references to removed commands"** (per D-08)

1. **No references to removed /plan command** -- Scan all command .md files and SKILL.md files across all plugins for the string `/plan` that is NOT preceded by `/gsd:plan` and NOT part of a larger word. If found in a context that suggests it's a command reference (not documentation), flag it. Use a pragmatic approach: grep for `/plan ` or `/plan\n` patterns. A simpler check: search for the exact strings `/plan`, `/build`, `/status` as standalone command references in command files.

2. **No references to removed /build command** -- Same scan for `/build` as a standalone command reference.

3. **No references to removed /status command** -- Same scan for `/status` as a standalone command reference. Note: `/gsd:status` is valid if it exists; only bare `/status` is dangling.

4. **Ecosystem totals are reasonable** -- Count total commands, skills, agents across all plugins + GSD. Assert totals are > 0 for each category. Print summary for documentation: "Ecosystem: N commands, M skills, K agents across P plugins."

Use `const PROJECT_ROOT = path.join(__dirname, '..')` for path resolution.
Use `node:test` describe/it pattern, `node:assert/strict`.
No temp directories needed -- this test reads the real project filesystem (read-only).
