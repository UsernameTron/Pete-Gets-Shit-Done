### Task 1: Add deepFreeze() Utility to core.cjs

**File:** `get-shit-done/bin/lib/core.cjs`
**Insert after:** The `debugLog` function (line ~60), within the "Core — Shared utilities" section near the top.

**Implementation:**

```javascript
/**
 * Recursively freeze a plain object or array.
 * Skips non-plain-object values (Date, RegExp, Buffer, etc.) and null/undefined.
 * Safe to call on already-frozen objects (no-op).
 */
function deepFreeze(obj) {
  if (obj === null || obj === undefined || typeof obj !== 'object') return obj;
  if (Object.isFrozen(obj)) return obj;
  Object.freeze(obj);
  const keys = Object.keys(obj);
  for (let i = 0; i < keys.length; i++) {
    const val = obj[keys[i]];
    if (val !== null && typeof val === 'object' && !Object.isFrozen(val)) {
      deepFreeze(val);
    }
  }
  return obj;
}
```

**Design choices:**
- Uses `Object.keys()` instead of `Object.getOwnPropertyNames()` to match how the codebase accesses properties (only own enumerable).
- Returns the input for chaining convenience (`return deepFreeze(result)`).
- Skips frozen objects to be safe for idempotent calls.
- No prototype check for `Array.isArray` — `Object.freeze` works correctly on arrays (prevents `.push()`, index assignment, `.length` changes).

**Export:** Add `deepFreeze` to the `module.exports` block at line 1293.

**Tests:** Add to `tests/core.test.cjs`:

1. `deepFreeze freezes a plain object` — `assert.ok(Object.isFrozen(deepFreeze({ a: 1 })))`
2. `deepFreeze freezes nested objects recursively` — nested `{ a: { b: { c: 1 } } }`, assert all levels frozen
3. `deepFreeze freezes arrays` — `[1, [2, 3]]`, assert outer and inner frozen
4. `deepFreeze handles mixed objects and arrays` — `{ items: [{ id: 1 }] }`, assert object, array, and nested object all frozen
5. `deepFreeze returns null/undefined/primitives unchanged` — no throw
6. `deepFreeze is idempotent on already-frozen objects` — call twice, no throw
7. `deepFreeze prevents mutation` — frozen object, `assert.throws(() => { obj.x = 1 })` in strict mode

**Acceptance criteria:**
- [ ] `deepFreeze` exported from core.cjs
- [ ] Recursively freezes plain objects and arrays
- [ ] Returns primitives, null, and undefined without throwing
- [ ] Idempotent on already-frozen objects
- [ ] All 7 new tests pass

### Task 2: Apply deepFreeze at Module Boundary Return Points

**Requirement:** CORR-05 — Freeze return values at module boundaries.

#### 2a. Freeze `loadConfig()` return value

**File:** `get-shit-done/bin/lib/core.cjs`
**Lines:** 383 and 420 (two return statements in `loadConfig`)

**Change at line 383** (successful parse path):
```javascript
// Before:
return {
  model_profile: get('model_profile') ?? defaults.model_profile,
  // ... all fields ...
};

// After:
return deepFreeze({
  model_profile: get('model_profile') ?? defaults.model_profile,
  // ... all fields ...

```

**Change at line 420** (fallback/catch path):
```javascript

// After:
```

**Why:** `loadConfig()` is the most consumed accessor in the codebase. Freezing here transitively protects `cmdStateLoad` (which embeds the config in its return value) and every other caller.

#### 2c. Freeze state.cjs command returns

State command functions pass their results through `output()`, which serializes to JSON before writing to stdout. The `output()` function itself does not return the object to the caller. For commands invoked via the CLI (`gsd-tools.cjs`), the object is serialized and the process exits — freezing is irrelevant.

However, two exported helper functions return objects that other modules consume directly:
- `stateExtractField` — returns string or null (immutable, no freeze needed)
- `stateReplaceField` / `stateReplaceFieldWithFallback` — returns string or null (immutable, no freeze needed)

**Decision:** State command returns go through `output()` which serializes. No freeze needed at state.cjs boundaries. The `loadConfig()` freeze in Task 2a already protects the config sub-object embedded in `cmdStateLoad`'s result.

#### 2d. Freeze phase.cjs internal returns

## Risk Assessment

**Low risk.** `Object.freeze` is shallow and well-understood. `deepFreeze` adds recursion but only on plain objects. The primary risk is that existing code somewhere mutates a `loadConfig()` return value — which would be caught immediately as a runtime TypeError in strict mode. The test suite will surface any such cases.

**Mitigation:** Run the full test suite after applying freezes. Any test that mutates a returned config or state object will fail, revealing the problematic pattern to fix.
