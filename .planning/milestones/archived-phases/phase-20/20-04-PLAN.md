# Plan 20-04: Skill-Forge Consolidation

## Objective
Merge skill-forge engineering patterns (validation, quality checks, structure enforcement) into the core GSD skill registry. The skill-forge is an external Claude Code skill/protocol — not code in get-shit-done. This plan internalizes its quality gates as registry functions.

## Background
The skill-forge protocol enforces:
1. Required frontmatter fields (name, description)
2. Name format validation (lowercase, hyphens, <=64 chars)
3. Description quality (non-empty, <=1024 chars, includes trigger terms)
4. File structure checks (SKILL.md exists, reasonable size)
5. No redundant/stale content

These checks currently happen only when the skill-forge skill is manually invoked. Consolidation means the registry itself can validate skills on load.

## Tasks

### Task 1: validateSkillMetadata(metadata) in init.cjs
- Accept parsed metadata object (from `parseSkillMetadata` in 20-01)
- Validate required fields: `name` (required), `description` (required)
- Validate name format: `/^[a-z0-9][a-z0-9-]*$/`, length <= 64
- Validate description: non-empty, length <= 1024
- Return `{ valid: boolean, warnings: [...], errors: [...] }`
- Warnings for: description too short (<20 chars), missing version field
- Errors for: missing name, invalid name format, missing description, description too long

### Task 2: validateSkillStructure(skillPath, projectRoot) in init.cjs
- Check SKILL.md exists (already done in buildAgentSkillsBlock, but formalize)
- Check SKILL.md is readable and non-empty
- Check file size reasonable (warn if > 50KB — suggests bloated skill)
- Check for supporting files pattern (optional: REFERENCE.md, EXAMPLES.md)
- Return `{ valid: boolean, warnings: [...], errors: [...], files: [...] }`

### Task 3: Integrate validation into buildAgentSkillsBlock
- After checking SKILL.md existence, optionally validate metadata
- Controlled by feature flag: `features.skill_validation` (from Phase 19 feature flags)
- When enabled: parse metadata, run validation, emit warnings to stderr
- When disabled (default): behave exactly as before
- This is the consolidation: registry validates on load, not just checks existence

### Task 4: Wire validate-skill CLI command
- Add `validate-skill <path>` case in gsd-tools.cjs
- Route to `init.cmdValidateSkill(cwd, skillPath, raw)`
- Runs both metadata and structure validation
- Output: JSON (raw) or formatted report (default)
- Exit code 0 = valid, exit code 1 = errors found

### Task 5: Tests (10+ tests)
- `validateSkillMetadata`: valid metadata passes, missing name errors, invalid name format, short description warns, long description errors, missing description errors
- `validateSkillStructure`: valid structure, missing SKILL.md, empty SKILL.md, oversized SKILL.md
- Integration: buildAgentSkillsBlock with feature flag on emits validation warnings
- Integration: buildAgentSkillsBlock with feature flag off skips validation (backward compatible)
