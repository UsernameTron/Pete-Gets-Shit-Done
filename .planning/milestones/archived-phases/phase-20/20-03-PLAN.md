# Plan 20-03: Skill Versioning

## Objective
Add version tracking to skill metadata, support version-pinned references in config, and emit warnings when skill versions drift from configured expectations.

## Tasks

### Task 1: Version-pinned reference support in buildAgentSkillsBlock
- Support `path@version` syntax in config: `"skills/my-skill@1.2.0"`
- Parse into `{ path: "skills/my-skill", expectedVersion: "1.2.0" }`
- When version is pinned, parse SKILL.md frontmatter (via `parseSkillMetadata` from 20-01)
- Compare `expectedVersion` with `metadata.version`
- Emit stderr warning if mismatch: `[agent-skills] WARNING: Version drift — skills/my-skill expects 1.2.0, found 1.3.0`
- Unversioned references (no `@`) work as before — no version check

### Task 2: checkSkillVersions(cwd) utility in init.cjs
- Load config, iterate all agent_skills entries
- For each versioned reference, compare against SKILL.md frontmatter version
- Return `{ matches: [...], drifts: [...], unversioned: [...], missing_version: [...] }`
- `drifts`: entries where expected != actual
- `missing_version`: entries where config pins a version but SKILL.md has no version field

### Task 3: Wire CLI command
- Add `check-skill-versions` case in gsd-tools.cjs
- Route to `init.cmdCheckSkillVersions(cwd, raw)`
- Output: JSON (raw) or formatted report (default)

### Task 4: Tests (8+ tests)
- Unversioned reference: no warning emitted
- Versioned reference with matching version: no warning
- Versioned reference with drift: warning emitted
- Missing version in SKILL.md: warning emitted
- `checkSkillVersions`: mixed results with all categories
- `@` parsing edge cases: no version after @, empty string
- buildAgentSkillsBlock still works with versioned refs (path extracted correctly)
