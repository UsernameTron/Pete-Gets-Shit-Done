# PLAN — Phase 14-01: Timeout Guards & Graceful Degradation

## Overview

Add configurable timeouts and diagnostic logging to synchronous shell operations. Three tasks targeting core.cjs and tests/core.test.cjs.

## Task 1: safeExec() wrapper (CORR-07)

**Goal:** Create a safe execution wrapper that adds timeout support to shell operations.

**Steps:**
1. Add `safeExec(command, args, options)` function to core.cjs
2. Accept `options.timeout` (default 30000ms), `options.cwd`, `options.encoding` (default 'utf-8')
3. Use `spawnSync(command, args, { ...options, stdio: 'pipe', timeout })` — Node's built-in timeout
4. Return structured result: `{ ok: exitCode === 0 && !timedOut, exitCode, stdout, stderr, timedOut }`
5. Detect timeout via `result.signal === 'SIGTERM'` or `result.error?.code === 'ETIMEDOUT'`
6. Export from module.exports
7. Add unit tests: success case, failure case (non-zero exit), timeout case, default timeout

**Files:** core.cjs, tests/core.test.cjs

## Task 2: Refactor execGit() to use safeExec() (CORR-08)

**Goal:** Wire execGit through safeExec so all git operations get timeout protection.

**Steps:**
1. Rewrite execGit to call `safeExec('git', args, { cwd, timeout: 30000 })`
2. Map safeExec result to existing execGit return shape: `{ exitCode, stdout, stderr }`
3. Add `timedOut` field to execGit return for callers that want it
4. Verify all 18 callers still work (existing tests cover this)
5. Add test for execGit timeout propagation

**Files:** core.cjs, tests/core.test.cjs

## Task 3: withPlanningLock() force-acquire diagnostics (CORR-09)

**Goal:** Add diagnostic logging when the planning lock is force-acquired after timeout.

**Steps:**
1. Before force-deleting the lock file at line 663, read its contents with a try/catch
2. Parse the lock JSON to extract `pid`, `cwd`, and `acquired` timestamp
3. Call `debugLog()` with a message like: `"Planning lock force-acquired — stale lock held by PID {pid} since {acquired} in {cwd}"`
4. If lock contents are unreadable, log: `"Planning lock force-acquired — could not read stale lock details"`
5. Add test: verify debugLog is called on force-acquire path (mock the timing)

**Files:** core.cjs, tests/core.test.cjs
