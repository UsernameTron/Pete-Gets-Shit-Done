# Plan 3: Catch Block Audit Across Remaining Lib Modules

## Overview

Systematic audit and remediation of all ~138 catch blocks across the 14 remaining lib modules (excluding core.cjs which is handled in Plan 2). Each catch block gets one of three treatments: annotated as intentionally silent, enhanced with debug logging, or converted to propagate GsdError. No behavior changes — this is a documentation and observability pass.

## Classification Rules

Apply these rules consistently across all files:

| Pattern | Treatment | Example |
|---------|-----------|---------|
| Filesystem race (file may vanish between check and read) | `/* intentional: [specific race] */` | stat after readdir |
| Best-effort cleanup (rm, rmdir, unlink in error handlers) | `/* intentional: best-effort cleanup */` | cleanup in catch/finally |
| Parse fallback (JSON.parse with fallback value) | `/* intentional: parse failure returns [fallback] */` | JSON.parse with default |
| Feature detection (checking if something exists) | `/* intentional: [feature] not available */` | git check-ignore |
| Read with null/default return | `/* intentional: missing file returns [default] */` | safeReadFile pattern |
| Error that should be observable in debug | `debugLog(CODE, message, context)` | Config write failures |
| Already handles error properly | Leave as-is | `catch (err) { output({error: err.message}) }` |
