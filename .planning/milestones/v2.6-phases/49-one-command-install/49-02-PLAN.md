**Test structure:**

```javascript
'use strict';
const { describe, it } = require('node:test');
const assert = require('node:assert/strict');
const { execFileSync } = require('child_process');
const fs = require('fs');
const path = require('path');

const PROJECT_ROOT = path.resolve(__dirname, '..');
const SCRIPT_PATH = path.join(PROJECT_ROOT, 'bin', 'setup-from-clone.js');
```

**Test groups:**

1. **describe('setup-from-clone.js file structure'):**
   - `it('exists at bin/setup-from-clone.js')` — assert file exists
   - `it('has valid JavaScript syntax')` — run `execFileSync(process.execPath, ['-c', SCRIPT_PATH])`, assert no throw
   - `it('starts with shebang line')` — read first line, assert starts with `#!/usr/bin/env node`
   - `it('uses strict mode')` — read file content, assert contains `'use strict'`
   - `it('has no external dependencies')` — read file, regex for `require\(` calls, assert every require is for `fs`, `path`, `os`, or `child_process` (Node.js built-ins only)

2. **describe('setup-from-clone.js integration'):**
   - `it('runs without error and exits 0')` — run `execFileSync(process.execPath, [SCRIPT_PATH], { cwd: PROJECT_ROOT, timeout: 120000 })`, assert no throw. Capture stdout.
   - `it('produces verification output with PASS/FAIL markers')` — from captured stdout (run script, capture output as string via `encoding: 'utf8'`), assert output includes `PASS` or `SKIP` (at least one verification line)
   - `it('reports command count in verification')` — assert stdout contains `commands` (verification mentions command count)
   - `it('reports hook count in verification')` — assert stdout contains `hook` (verification mentions hooks)

3. **describe('package.json setup script'):**
   - `it('has setup script defined')` — require `../package.json`, assert `scripts.setup === 'node bin/setup-from-clone.js'`

4. **describe('idempotency'):**
   - `it('second run produces skip results')` — run script twice, capture second run stdout, assert it contains `SKIP` (at least some items skipped on re-run per D-08)

**Important notes:**
- The integration tests run the actual script, which modifies `~/.claude/`. This is acceptable because the script is idempotent and the test environment is the developer's own machine (not CI).
- Set `timeout: 120000` (2 minutes) on integration tests since npm install may run.
- Use `execFileSync` (not `exec`) for subprocess invocation in tests.
