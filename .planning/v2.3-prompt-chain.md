# v2.3 Charter Analysis & Prompt Chain

## Ultrathink: 4-Perspective Analysis of 13 Charter Candidates

### Architect

The 13 candidates sort into 4 natural themes:

| Theme | Items | Effort | Dependency |
|-------|-------|--------|------------|
| **A. Security** | #4 (Guardian agent), #6 (threat modeling), #12 (prompt injection hook) + ECC config-protection + governance-capture hooks | Medium | Builds on v2.2 hardening momentum |
| **B. Agent Quality** | #7 (4D scoring rubric), #8 (necessity gate), #9 (two-mode verify) | Medium | Extends gsd-verifier + subagent workflow |
| **C. Developer Experience** | #1 (PR opener), #11 (discuss flows), #13 (doc drift) | Medium | Standalone — no blockers |
| **D. Architecture Evolution** | #2 (pipeline mode), #3 (live coordination), #10 (skill restructure) | Large | Requires design phase, touches core execution engine |

Theme D is v2.5+ material — touching the execution engine and restructuring 47+ skills is a multi-milestone effort. Themes A+B are the right v2.3 scope: they continue v2.2's hardening trajectory and make GSD's agent ecosystem more robust before Pete stress-tests it at a new job.

### Research

The ECC diamond hunt surfaced 10 hook port candidates. Three have the highest ROI for GSD:

1. **config-protection.js** (~110 LOC, has tests) — blocks agents from weakening linter/formatter configs. Common LLM failure mode.
2. **cost-tracker.js** (~80 LOC, has tests) — token-level cost tracking to JSONL. GSD has zero cost telemetry today.
3. **prompt injection detection** (~50 LOC from gsd-prompt-guard.js, 18 regex patterns) — defense-in-depth for agent inputs.

The Claude-Backstage RETROSPECTIVE.md lesson — "worktree isolation on Wave 2 plans caused stalls" — is an operational bug worth documenting in gsd-executor's completion_criteria. Low effort, high impact for daily use.

### Coder

v2.2 had 2 phases and shipped in ~2 sessions. That cadence works for Pete. v2.3 should be 3-4 build phases + 1 audit. Anything bigger risks scope creep.

The hook ports are the easiest wins — source code exists, tests exist, adaptation is mostly path/naming changes. The Security Guardian is medium effort: ~250 LOC new agent file + threat model reference doc. The 4D scoring rubric extends an existing agent (gsd-verifier), not a new one.

Items #8 (necessity gate) and #9 (two-mode verify) are pattern integrations, not standalone features. They modify existing workflows rather than adding new surface area. Good for a single phase together.

### Tester

Hook ports carry their own test suites from source repos — adapt and run. The Security Guardian needs the same defense-in-depth standard the CREW assessment just established (10/10). The scoring rubric needs test cases for each dimension (security 35%, perf 25%, correctness 25%, maintainability 15%).

Item #5 (stack-analyzer) is already shipped — strike it.
