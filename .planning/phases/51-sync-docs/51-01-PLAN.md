**Frontmatter:**
```yaml
---
name: gsd:sync-docs
```

**Objective section:**
State that this command synchronizes README.md, CLAUDE.md, .planning/PROJECT.md, docs/DEVOPS-HANDOFF.md, and CHANGELOG.md to match live codebase reality. Runs inline — no agent delegation (per D-10, D-11). If `--dry-run` is passed via `$ARGUMENTS`, report what would change but do not write files.

**Process section with these exact numbered steps:**

**Step 0: Parse Arguments**
Check `$ARGUMENTS` for `--dry-run` flag. If present, set dry-run mode — collect all changes but do not write them. Report at end as "would update" instead of "updated".

**Step 1: Measure Live Codebase State (per D-01 — run live every time, no caching)**

Run these commands and capture output:
```bash
# Command count (will include this new command)
ls commands/gsd/*.md | wc -l

# Agent count (per D-02 — gsd-*.md, exclude _archived/)
ls agents/gsd-*.md 2>/dev/null | wc -l

# Skill count (per D-02)
ls -d plugins/*/skills/*/ 2>/dev/null | wc -l

# Version
node -e "console.log(require('./package.json').version)"

# Test stats (per D-03 — run npm test, parse output)
npm test 2>&1 | tail -5

# Coverage (per D-03 — run test:coverage, parse "All files" line)
npm run test:coverage 2>&1 | grep "All files"
```

Store results in a structured set of variables:
- `command_count` (integer)
- `agent_count` (integer)
- `skill_count` (integer)
- `version` (string)
- `test_suite_count` (integer, parse from npm test output)
- `test_assertion_count` (integer, parse from npm test output)
- `coverage_pct` (string, parse from coverage output "All files" line)

Also measure planning state:
```bash
# Current milestone
grep "^milestone:" .planning/STATE.md | head -1

# Phase count
ls -d .planning/phases/*/ | wc -l

# Completed phases (grep for [x] in ROADMAP)
grep -c '\[x\]' .planning/ROADMAP.md 2>/dev/null || echo 0
```

**Step 2: Read Current Doc Values**

For each target doc, read the file and extract current numeric values using grep/regex. Build a comparison table:

| Metric | Live Value | README.md Value | CLAUDE.md Value | PROJECT.md Value | DEVOPS Value |
|--------|-----------|-----------------|-----------------|------------------|--------------|

Search each file for patterns like:
- `\d+ slash commands` or `\d+ commands`
- `\d+ built-in agents` or `\d+ agents`
- `\d+ skills` or `\d+ Claude Code skills`
- `\d+ test suites` or `\d+ assertions`
- Coverage percentage patterns like `\d+%`
- Milestone names and status strings

Record every value found and whether it matches the live measurement. This is the "old value" for the diff report (per D-09).

**Step 3: Update README.md (per SDOCS-04)**

For each stale value found in Step 2, use the Edit tool to replace the old value with the live value. Preserve all surrounding text. Only touch lines where values are stale.

Specific patterns to update:
- `**63 slash commands**` or similar → replace number with `command_count`
- `**17 built-in agents**` or similar → replace number with `agent_count`
- `**45 Claude Code skills**` or similar → replace number with `skill_count`
- `**479 test suites, 2,490 assertions**` or similar → replace with live counts
- Coverage thresholds line → update if percentages changed
- Version references → update with live version

**Step 4: Update CLAUDE.md (per SDOCS-04)**

Same pattern as Step 3 but for CLAUDE.md. Update:
- Command count references (e.g., "63 slash commands")
- Agent count references (e.g., "17 built-in agents")
- Skill count references (e.g., "45 Claude Code skills")
- Test stats (e.g., "479 test suites, 2,490 assertions")

**Step 5: Update .planning/PROJECT.md (per SDOCS-03, SDOCS-04)**

Update milestone status, phase history, and any numeric references. Read `.planning/STATE.md` and `.planning/ROADMAP.md` as sources of truth for:
- Current milestone name and version
- Phase count and completion status
- Milestone history table

**Step 6: Update docs/DEVOPS-HANDOFF.md (per SDOCS-04)**

Update test stats, coverage numbers, version, and any environment requirements that reference specific counts.

**Step 7: Update CHANGELOG.md (per SDOCS-05, D-04, D-05, D-06)**

Generate new entries from git history:
```bash
# Find last tag (per D-04)
git describe --tags --abbrev=0 2>/dev/null || echo "none"

# Get commits since that tag (or all commits if no tag)
git log [tag]..HEAD --oneline --no-merges
```

Parse conventional commit prefixes and group:
- `feat:` commits → `### Added` section
- `fix:` commits → `### Fixed` section
- `docs:`, `chore:`, `refactor:`, `test:`, `perf:` → `### Changed` section

If an `[Unreleased]` section exists in CHANGELOG.md, append new entries there. If not, create one at the top of the file (below the header). Do not duplicate entries already present — check commit hashes or message text.

Keep a Changelog format strictly (per D-06):
```markdown
## [Unreleased]

### Added
- feat: description (commit-hash)

### Changed
- docs: description (commit-hash)

### Fixed
- fix: description (commit-hash)
```

**Step 8: Generate Diff Report (per SDOCS-06, D-07, D-08, D-09)**

Print an inline terminal table summarizing all changes:

```
Sync Docs Report
================

| File              | Section Updated    | Old Value           | New Value           |
|-------------------|--------------------|---------------------|---------------------|
| README.md         | command count      | 63 slash commands   | 64 slash commands   |
| CLAUDE.md         | test stats         | 479 suites          | 485 suites          |
| CHANGELOG.md      | unreleased entries | 0 entries           | 12 entries added    |
| ...               | ...                | ...                 | ...                 |

Summary: 4 files updated, 8 sections changed, 0 files skipped.
```

If `--dry-run`, prefix with "DRY RUN — no files were modified:" and change "updated" to "would update".

If all values already match (nothing stale), print: "All documentation is current. No changes needed."
