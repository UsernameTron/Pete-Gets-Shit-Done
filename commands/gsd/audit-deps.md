<!-- workflow-exemption: inline — orchestration is simple enough to live inline (spawns gsd-dependency-auditor agent directly) -->
<objective>
Run a full dependency audit across every package manager detected in the current project (npm/pnpm/yarn, pip/poetry/uv, cargo, go mod, bundler, composer). Produces a BLOCK/FLAG/PASS verdict with a committable report at `.planning/dependencies/DEPENDENCIES-REPORT.md`.

**This command spawns the `gsd-dependency-auditor` agent and post-processes its output.** It does not contain audit logic itself — all manager detection, tool invocation, and finding classification lives in the agent. This command handles: flag parsing, spawning, branch/commit housekeeping, and user-facing summary.

**Convention note:** Unlike other GSD commands, this one does NOT have a companion workflow file at `~/.claude/get-shit-done/workflows/audit-deps.md`. The orchestration is simple enough to live inline. If this command grows its own pre/post processing logic (beyond flag parsing), extract to a workflow file at that time.
</objective>

<arguments>
Parse `$ARGUMENTS` for these flags. Missing flags default to the behaviors noted.

- `--no-commit` — Do NOT auto-commit `DEPENDENCIES-REPORT.md` after the audit. Default: auto-commit on a `chore/dependency-audit-<timestamp>` branch.
- `--quiet` — Suppress the SUMMARY echo to the user. Default: echo the SUMMARY block after the audit completes.
- Any other argument is ignored with a warning.
</arguments>

<process>

## Step 1: Pre-flight checks

Verify we're in a git repo and the current directory has at least one supported manifest file:

```
Bash: git rev-parse --show-toplevel 2>/dev/null
```

If this fails, the project is not a git repo. Warn the user and continue anyway — the audit itself does not require git, only the auto-commit does. If the user passed `--no-commit`, a missing git repo is fine.

Check for at least one supported manifest:

```
Glob: package.json, pnpm-lock.yaml, pyproject.toml, requirements.txt, Cargo.toml, go.mod, Gemfile, composer.json
```

If zero manifests are found, print:

```
No supported package manifest found in this directory. /gsd:audit-deps supports:
  npm/pnpm/yarn, pip/poetry/uv, cargo, go mod, bundler, composer
```

…and stop. Do not spawn the agent.

## Step 2: Spawn the auditor agent

Invoke `gsd-dependency-auditor` via the Task tool with `subagent_type: gsd-dependency-auditor`.

Prompt the agent with:

```
Perform a full dependency audit of the current working directory.

<files_to_read>
(list every manifest file found in Step 1)
</files_to_read>

Audit scope: security (CVEs), staleness (stale/outdated prod deps), licenses.

Write your structured report to `.planning/dependencies/DEPENDENCIES-REPORT.md` following the format specified in your role instructions. Echo the SUMMARY block to stdout so I can surface it to the user.

Respect all rules in your <anti_patterns> section. Specifically: no minor-version upsells, no invented CVE numbers, no file modifications outside the single report file.
```

Wait for the agent to complete. Capture its response text.

## Step 3: Verify the report exists

```
Bash: test -f .planning/dependencies/DEPENDENCIES-REPORT.md && echo "report exists" || echo "report missing"
```

If the report is missing, the agent failed. Print the agent's response text verbatim so the user can diagnose, and stop. Do NOT proceed to commit.

## Step 4: Extract and display the SUMMARY block (unless --quiet)

If `--quiet` was NOT passed:

```
Bash: sed -n '/--- SUMMARY ---/,/--- SECURITY FINDINGS ---/p' .planning/dependencies/DEPENDENCIES-REPORT.md
```

Print the result to the user so they see the verdict immediately.

## Step 5: Commit the report (unless --no-commit)

If `--no-commit` was passed, skip this step and tell the user: "Report written to `.planning/dependencies/DEPENDENCIES-REPORT.md` (not committed, per --no-commit)."

Otherwise:

```
Bash: git rev-parse --abbrev-ref HEAD
```

If the current branch is `main` or `master`, create a new branch:

```
Bash: git checkout -b chore/dependency-audit-$(date +%Y%m%d-%H%M%S)
```

Then:

```
Bash: git add .planning/dependencies/DEPENDENCIES-REPORT.md
Bash: git commit -m "chore: dependency audit report

Verdict: <extracted from SUMMARY>
Generated by /gsd:audit-deps
"
```

Print the resulting commit hash and branch name to the user.

## Step 6: Extract the overall verdict and exit appropriately

Parse the verdict from the SUMMARY:

```
Bash: grep -m1 "^Overall verdict:" .planning/dependencies/DEPENDENCIES-REPORT.md | awk '{print $3}'
```

Report to the user in one line:

- `PASS` → "Dependency audit: PASS. No action required."
- `FLAG` → "Dependency audit: FLAG. Review `.planning/dependencies/DEPENDENCIES-REPORT.md` for non-blocking issues."
- `BLOCK` → "Dependency audit: BLOCK. `.planning/dependencies/DEPENDENCIES-REPORT.md` contains critical issues that should be fixed before shipping."

</process>

<examples>

**Clean run (default):**
```
/gsd:audit-deps
```
→ Spawns agent, writes report, commits on `chore/dependency-audit-<ts>` branch, echoes SUMMARY + one-line verdict.

**Rapid iteration (no commit):**
```
/gsd:audit-deps --no-commit
```
→ Spawns agent, writes report, echoes SUMMARY, leaves report uncommitted for the user to decide.

**CI-friendly (quiet + no commit):**
```
/gsd:audit-deps --no-commit --quiet
```
→ Spawns agent, writes report, prints only the one-line verdict. Useful inside larger orchestration.

</examples>

<anti_patterns>
<what_not_to_do>
1. **Do NOT run audit commands directly in this command file.** All audit logic lives in `gsd-dependency-auditor`. This file is orchestration only.
2. **Do NOT parse the DETAILED FINDINGS section.** It is optional enrichment for humans; downstream tooling uses only the content between `=== GSD DEPENDENCY AUDIT REPORT ===` and `=== END REPORT ===`.
3. **Do NOT commit directly to main/master** even if the pre-commit hook is disabled. Always branch first.
4. **Do NOT try to auto-fix BLOCK verdicts.** This command reports; it does not remediate. Remediation is a separate phase.
5. **Do NOT run if no manifest is found.** Spawning the agent for a manifest-free directory wastes tokens. Short-circuit in Step 1.
</what_not_to_do>
</anti_patterns>
